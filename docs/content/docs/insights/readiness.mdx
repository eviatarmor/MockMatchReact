Readiness summarizes how prepared you look across documents, practice, and applications, and highlights next steps that lift weaker areas.

## Open Readiness

In the signed-in app: **Insights** area → **Readiness** (`/readiness`).

## What you see

Typical surfaces include:

- An **overall readiness** signal
- Stats such as active applications and completed mock interviews
- **Readiness by area** (for example resume health, behavioral, coding, case studies, system design)
- **Next up** recommendations aimed at weaker areas
- **Session history** for scored practice runs

Use the page to pick one concrete action: fix resume keywords, run a mock track, or move an application stage. Avoid treating the overall number as the product.

## How to act on a weak area

| Signal | Sensible next step |
|--------|--------------------|
| Resume health | Open [Resume Lab](/docs/documents/resume-lab); for a specific job use [Discover](/docs/jobs/discover) fit |
| Coding / system design | Open [Simulations](/docs/practice/simulations) or filtered [Question Bank](/docs/practice/question-bank) |
| Behavioral | Run a conversation track |
| Thin pipeline | Discover or import jobs into [Applications](/docs/jobs/applications) |

## Export

If **Export report** or CSV export appears on session history, use it when you want an offline snapshot. Availability follows the current product UI.
